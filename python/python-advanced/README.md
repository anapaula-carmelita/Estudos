## 🎯 Project Vision and Motivation

As a Systems Analyst acting as a **Software Engineer**, I believe in treating study projects with the same rigor as production software. 

To reflect real-world development practices, this project bridges the gap between learning requirements and technical implementation. I am treating this 5-course curriculum as a major software product release cycle. My methodology includes:

*   **User Story Mapping:** Visualizing the learning journey across all five courses.
*   **Agile Execution:** Managing tasks via GitHub Projects (Kanban) using releases and time-boxed Sprints.
*   **Requirements Analysis:** Documenting the logic, constraints, and needs for every lab script before coding.
*   **Engineering Focus:** Prioritizing deep technical understanding, architecture, and code quality over exam-cramming.

## 🗺️ Requirements & Agile Planning Overview

This project is structured using standard Agile taxonomy to break down the complexity of the 5 advanced Python courses into deliverable increments.

### 1. The Epic: Advanced Python Mastery (PCPP1 Track)
* **Goal:** Attain practical, deep mastery of advanced Python concepts by solving all proposed labs in the PCPP1 curriculum.
* **Scope:** The complete set of 5 courses provided by the Python Institute for the professional level.

### 2. Releases (The Courses)
The Epic is divided into five major Releases (representing each specific course of the track). These act as the major milestones of my learning journey:
* **Release 1:** Advanced Object-Oriented Programming (OOP).
* **Release 2:** Coding Conventions, Best Practices, and Standardization (PEP 8, PEP 257).
* **Release 3:** GUI Programming (Tkinter).
* **Release 4:** Network Programming (RESTful APIs, Sockets).
* **Release 5:** File Processing and Environment (XML, SQLite, CSV, Logging, Configparser).

### 3. User Stories (The Labs)
Each Release is broken down into specific User Stories, which are the **practical laboratories**. 
* Each User Story (Lab) acts as a standalone requirement.
* Before coding, each story receives its own documentation detailing the **Business Logic** and **Acceptance Criteria**.
